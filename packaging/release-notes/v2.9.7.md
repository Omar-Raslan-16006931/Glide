## What's new in 2.9.7

**Smoother live play with frame generation.** Live play could look less smooth than a recording of the same moment. With frame generation the output runs near your screen's refresh rate. In the old default display mode ("Automatic") a new frame could replace one that hadn't been shown yet, so now and then a generated frame was skipped and the next screen refresh repeated a frame. Recordings keep every frame, which is why they looked smoother.

The new **Smooth frame pacing** switch in the quick setup is on by default:
- **What it does:** shows every frame at a screen refresh (V-Sync), asks for variable refresh (G-SYNC/FreeSync) where your screen supports it, and caps the output at your refresh rate. Every generated frame is shown once, so playing looks like the recording.
- **Delay:** with variable refresh it adds almost none. Without it, a frame can wait up to one screen refresh.
- **Turning it off:** the switch goes back to the lowest-latency mode.
- **Your own choice is kept:** if you had already picked a display sync mode in Professional mode, 2.9.7 doesn't change it.

For the smoothest result:
- turn on G-SYNC/FreeSync in your graphics driver;
- play in fullscreen (F11);
- set your screen to its highest refresh rate in Windows.

**Also in this release (from 2.9.6):** in comparison clips, the console side no longer freezes for a few seconds when the encoder briefly falls behind.

**Tested how.** In CI on Windows:
- the build, unit tests, QML tests (including the new switch) and the install test.

The display modes it uses (V-Sync, variable refresh, output cap) are Veyra's existing, tested modes. Not yet tested on a real screen with a capture card: reports are welcome.

**Windows Defender note.** Defender may flag new Glide downloads as `Trojan:Win32/Tecabans.STV!cl`. This is a false positive from its cloud check on new, unsigned files, and it has been reported to Microsoft. Always check the zip against `SHA256SUMS.txt` on this page.
